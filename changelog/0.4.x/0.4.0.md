# 0.4.0 — 2026-11-25

## Added

- **11 catalog metrics** take the catalog from 49 to 60 ([#29](https://github.com/cyanheads/fdic-banks-mcp-server/issues/29)): `held_to_maturity_amortized_cost`, `held_to_maturity_fair_value`, `available_for_sale_amortized_cost`, `available_for_sale_fair_value`, `tier1_capital`, `total_risk_based_capital`, `risk_weighted_assets`, `agricultural_production_loans`, `farmland_loans`, `nonfarm_nonresidential_non_owner_occupied_loans`, and `cre_loans_not_secured_by_real_estate`. All are `usd_thousands`, `point_in_time`.

## Changed

- **`fdic_dataframe_query` refuses SQL that uses a DuckDB metadata-view name as a column alias (quoted or upper-case included), a CTE name, a table alias, or a subquery alias** (breaking), with reason `system_catalog_access`. The 35 names are `duckdb_tables` and the other `duckdb_*` views, `pg_tables` and the other `pg_*` views, `sqlite_schema`, `sqlite_temp_master`, `sqlite_temp_schema`, and `pragma_database_list` (`sqlite_master` was already refused). 0.3.0 answered those queries with correct values; rename the alias. The refusal comes from the mcp-ts-core 0.13.19 system-catalog guard.
- **`system_catalog_access` covers DuckDB's metadata views in `fdic_dataframe_query`**: a direct read that 0.3.0 refused as `plan_operator_not_allowed` (`SELECT * FROM duckdb_tables`) now fails with it, the reason's contract names the views, and its recovery says to rename an alias spelled like one.
- **`total_risk_based_capital` and `risk_weighted_assets` read `null` where FDIC reports `0`** (community bank leverage ratio filers) ([#29](https://github.com/cyanheads/fdic-banks-mcp-server/issues/29)). The zero-means-unreported note now also names uninsured trust companies, and the `metric_filters` description and zero-hit notice list the flagged metrics, so a bound on either skips those filers.
- **`nonfarm_nonresidential_loans` note** says the metric includes owner-occupied loans, and that the interagency CRE concentration test counts only the non-owner-occupied part ([#29](https://github.com/cyanheads/fdic-banks-mcp-server/issues/29)).
- **Canvas SQL admits `range()` and `generate_series()` as table functions with constant arguments** ([cyanheads/mcp-ts-core#822](https://github.com/cyanheads/mcp-ts-core/issues/822)).
- **`fdic-banks-guide` skill 1.1** warns that a Connecticut county comparison across 2022 and 2023 breaks (counties became planning regions) and points to `city` or `msa_code`.
- **Framework files** synced with mcp-ts-core 0.13.22: framework skills, `scripts/`, `changelog/template.md`, `.mcpbignore`, and `.env.example` (`MCP_JWT_EXPECTED_AUDIENCE`, `MCP_JWT_EXPECTED_ISSUER`). The `.mcpb` bundle also drops dependencies' root `AGENTS.md` and `CLAUDE.md`.

## Fixed

- **`St.`/`St`/`Saint`, `Ste.`/`Ste`/`Sainte`, `Ft.`/`Ft`/`Fort`, and `Mt.`/`Mt`/`Mount` spellings** of a `city` or `county` now all match, so `St. Louis` finds `Saint Louis` in `fdic_get_deposits` and `fdic_search_institutions` ([#27](https://github.com/cyanheads/fdic-banks-mcp-server/issues/27)). Only values of ASCII letters, digits, spaces, and `. ' ( ) -` expand, which keeps the longest request under FDIC's URL limit.
- **`fdic_get_deposits` `county` matches parishes, boroughs, and independent cities** ([#30](https://github.com/cyanheads/fdic-banks-mcp-server/issues/30)). ` County` is dropped everywhere and the other county-equivalent words only in their states (` Parish` in LA; ` City and Borough`, ` Borough`, ` Census Area`, ` Municipality` in AK; ` Municipality`, ` Municipio` in PR; ` Municipality` in MP; ` Planning Region` in CT), and a trailing ` City` or ` (City)` pairs with ` (City)` (`Richmond City` finds `Richmond (City)`). A Pennsylvania `X Borough` keeps its word and gets the empty market.
- **`fdic_search_institutions` `next_offset` walks return each match once** ([#28](https://github.com/cyanheads/fdic-banks-mcp-server/issues/28)). FDIC answers a name search in one of two orders, so offset pages repeated one match and skipped another. Each relevance tier and `status: inactive` search is read in 10,000-match chunks and pages are cut from them; a per-process record holds each chunk's CERT order, a chunk that disagrees with it is re-read up to 6 times, and a page whose order can't be confirmed carries a notice pointing to `sort`. `sort: name` and `assets_desc` break ties by `NAME,CERT` and `ASSET,CERT`. The first failed read of a page aborts the page's other reads and their retries.
- **`fdic_search_institutions` no longer offers a `next_offset` from an empty page** inside the match count; following it requested the same page again.
- **Direct reads of `pg_am`, `pg_tablespace`, and `pg_collation` in `fdic_dataframe_query` are refused**; 0.3.0 returned fixed engine values although the tool description says system catalogs are rejected.
