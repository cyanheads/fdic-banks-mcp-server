# 0.2.0 — 2026-10-16

## Changed

- **Failure assets/deposits are nullable when a nonempty set has no reported amounts**, across summary and grouped totals and by-method assets; missing counts cover every match independently of paging ([#17](https://github.com/cyanheads/fdic-banks-mcp-server/issues/17)). Recorded zero, partial sums, and empty-set zero remain distinct.
- **Oversized reads** execute within existing caps and disclose effective bounds, processed/deferred CERTs and metrics, and continuation; deferred peer cohorts are marked incomplete ([#20](https://github.com/cyanheads/fdic-banks-mcp-server/issues/20)). Panel/deposit previews and SQL previews accept larger values bounded by available data.
- **Dataframe SQL acceptance** narrows with mcp-ts-core 0.13.15: engine-setting functions, dynamic table lookup, nonliteral `query()` arguments, and literal `query()` nesting beyond four levels are refused. Replace these with SELECTs over staged tables and at most four literal-query levels.
- **Release policy and framework guidance** now require gated release review and synchronize the shipped framework skills with mcp-ts-core 0.13.15.

## Fixed

- **Empty selections** for CERTs, peer CERTs, bank classes, and failure methods reject before querying; omit the selector for unrestricted/default selection ([#16](https://github.com/cyanheads/fdic-banks-mcp-server/issues/16)).
- **SQL scope** uses DuckDB resolution for aliases, comments, quoted identifiers, and CTEs; actual missing tables retain restaging guidance ([#18](https://github.com/cyanheads/fdic-banks-mcp-server/issues/18)).
- **Text rendering** preserves literal HTML/Markdown, links, entities, backslashes, and pipes while keeping structured values intact; recorded multiline SQL renders as quoted code ([#19](https://github.com/cyanheads/fdic-banks-mcp-server/issues/19)).
