# 0.1.3 — 2026-10-09

## Added

- **Hosted endpoint** — `server.json` adds the `remotes` entry for `https://fdic-banks.caseyjhand.com/mcp`, and the README documents the public instance.

## Changed

- **mcp-ts-core** — `@cyanheads/mcp-ts-core` ^0.13.8 → ^0.13.14 — tool error results end with `request <id>` and carry `data.requestId` (0.13.10); an integer sent for a string field such as `name` is repaired (0.13.9), as are a numeric string for a number field such as `cert` and `null` at an optional key (0.13.14); MCP SDK `@modelcontextprotocol/server` ^2.0.0 → ^2.2.0, which refuses a 2026-07-28 POST without `MCP-Protocol-Version` and a JSON-RPC batch over 100 messages (0.13.9, 0.13.11).
- **Recovery hints** — handlers and services no longer forward `ctx.recoveryFor` and rely on the framework to fill the declared hint (internal; the recovery text callers receive is unchanged).
- **`server.json`** — npm entries drop the `run start:*` arguments and set `runtimeHint: "npx"`; the HTTP entry sets `MCP_TRANSPORT_TYPE` to `http`, so a registry client launching it starts HTTP.
- **Docker** — the `deps` stage runs `install-otel.ts` and `prune-musl-packages.ts`, dropping musl-only packages from the glibc image (mcp-ts-core 0.13.10, 0.13.11); the seeded security scanner stays out of the image.
- **Repo config** — `.env.example` documents `MCP_REQUEST_STATE_KEY` and `LOG_LLM_INTERACTIONS`; `.gitignore`, `.dockerignore`, and `.mcpbignore` follow the framework template; `codeql.yml` analyzes each language under `/language:<language>`; the CLAUDE/AGENTS/design docs match.

## Fixed

- **`fdic_dataframe_drop`** — an expired canvas returns `canvas_not_found` with its own recovery ("nothing is left to drop and no further call is needed"); it previously used the canvas service's hint to re-run a tool to stage fresh data.
- **Table cells** — `cell()` escapes `\` as well as `|`, so a `\|` in upstream text can no longer split a cell (#14).

## Security

- **#14** — `cell()` backslash escape in `src/mcp-server/tools/markdown.ts`; the SQL-literal pattern in `stripStringLiterals` now matches a backslash in exactly one way, output unchanged, which clears three code-scanning alerts.

## Dependencies

- `@duckdb/node-api` ^1.5.5-r.5 → ^1.5.6-r.1, `pino-pretty` ^13.1.3 → ^13.2.0; dev: `@biomejs/biome` 2.5.14 → 2.5.15, `@types/node` 26.6.2 → 26.6.4, `@vitest/coverage-istanbul` 5.0.1 → 5.0.3, `ignore` ^7.0.10 → ^7.0.12, `tsc-alias` ^1.9.5 → ^1.9.7, `vitest` ^5.0.1 → ^5.0.3.
